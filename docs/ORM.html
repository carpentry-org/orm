ORM

is a database-agnostic ORM layer for Carp.

The derive-model macro reads a type's field definitions via members and generates CRUD functions in the type's module. Backends plug into the macro by providing a small set of defndynamic helpers that control SQL dialect and row marshalling — see the backend API below.

Usage

(load "orm/backends/sqlite3.carp")

(deftype Item [id Int text String done Bool])
(derive-model Item SQLiteBackend [id Int])

This generates the following in the Item module:

  • create-table — (Fn [&Backend.Db] ())
  • insert — (Fn [&Backend.Db &Item] Int) — returns the new rowid
  • find-all — (Fn [&Backend.Db] (Result (Array Item) String))
  • find-by-id — (Fn [&Backend.Db &Pk] (Result Item String))
  • update — (Fn [&Backend.Db &Item] ()) — writes all data fields
  • delete-by-id — (Fn [&Backend.Db &Pk] ())

The primary-key argument is a reference even for value types (&Int).

Backend API

A backend is a module providing these defndynamic functions:

  • (sql-type t) — map a Carp type symbol to a SQL type string
  • (placeholder n) — parameter placeholder for position n (1-indexed)
  • (query-fn) — symbol of the static query function
  • (last-insert-id-sql) — SQL for fetching the id of the last inserted row
  • (extract-col t v) — form extracting a Carp value from an owned column variable v
  • (bind-value t expr) — form converting an expression expr into a bound parameter

See backends/sqlite3.carp for a working example.
